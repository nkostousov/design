# TEST DESIGN

This repository demonstrates the application of key **test design techniques** on practical examples of an online store project.  
Each document shows how different approaches help identify defects early, reduce redundant test cases, and ensure maximum coverage with minimum effort.

[Equivalence Partitioning Testing](https://docs.google.com/spreadsheets/d/1U75keq_Dfj04t-xmaFfJ37f6_ZQLyk3inchAFlK-D6M/edit?usp=sharing) - — identification of valid and invalid input classes for username and password fields; includes boundary testing (min/max length, prohibited symbols, character sets).  

[Pair testing](https://docs.google.com/spreadsheets/d/1wJ6BaYpehOK0XQxlEM6YJIQt3BhuvKeRcuOgk6zVtrQ/edit?usp=sharing) - — practical matrix for combining product filters (brand, category, sorting, free shipping) to ensure all logical combinations are verified and system behavior is consistent.

[Decision Table Testing](https://docs.google.com/spreadsheets/d/1z2kpDYXcTK5YariTFFDMOtUYyKsFKsF8_rIBk1KlYc8/edit?usp=sharing) - — modeling of business rules for account and transaction management; highlights expected results (Approve/Decline) for different rule combinations.

## What this repo demonstrates

- Transformation of requirements into structured, measurable test conditions.  
- Coverage optimization through **equivalence classes**, **boundary values**, and **decision logic tables**.  
- Examples of real analytical thinking and systematic test design for QA documentation.
